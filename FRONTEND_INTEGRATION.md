# Rihla - Frontend Integration & API Documentation

This document serves as the single source of truth for frontend developers connecting to the Rihla backend (Core-Server).

## 1. Global Setup & Requirements

- **Base URL**: `http://localhost:3000/api` (for local development)
- **Interactive API Docs (Swagger)**: You can test all endpoints visually at **`http://localhost:3000/api/docs`**.
- **Authentication**: JWT Bearer Tokens. Most endpoints require the `Authorization` header:
  ```http
  Authorization: Bearer <your_access_token>
  ```
- **CORS & Cookies**: Ensure your HTTP client (Axios/Fetch) is configured with `withCredentials: true`. The backend uses an HTTP-Only cookie for the refresh token. If you do not set this, the refresh token flow will fail.
- **Content-Type**: Default is `application/json` (except `/users/me/avatar` which is `multipart/form-data`).

---

## 2. Standard Error Formats

The backend uses a standard error format. Your frontend should be prepared to parse these:

**Generic Errors (401, 403, 404, 409, 500)**
```json
{
  "error": "Message describing the error"
}
```

**Validation Errors (400)** (Generated by Zod)
```json
{
  "error": "Validation error",
  "details": [
    {
      "code": "too_small",
      "minimum": 8,
      "type": "string",
      "inclusive": true,
      "message": "String must contain at least 8 character(s)",
      "path": ["password"]
    }
  ]
}
```

## 3. Authentication API (`/auth`)
*No JWT required for these endpoints except `/logout-all`.*

### `POST /auth/register`
Creates a new user account.
- **Body:**
  ```json
  {
    "email": "user@example.com",
    "password": "Password1",
    "display_name": "Ahmed",
    "gender": "MALE",
    "nationality": "Egypt",
    "language": ["ar", "en"],
    "travel_style": "Backpacker"
  }
  ```
- **Validation**: Password must be min 8 chars, 1 uppercase, 1 number. Gender: 'MALE' | 'FEMALE'.
- **Response `201`**: Returns created user object.

### `POST /auth/login`
Authenticates user. Returns access token in JSON and refresh token in an HTTP-Only cookie.
- **Body:**
  ```json
  {
    "email": "user@example.com",
    "password": "Password1"
  }
  ```
- **Response `200`**:
  ```json
  {
    "accessToken": "eyJhbGciOi...",
    "user": { "id": "uuid", "email": "user@example.com", "displayName": "Ahmed" }
  }
  ```

### `POST /auth/refresh`
Refreshes the expired access token.
- **Headers**: Browser will automatically send the HTTP-Only cookie if `withCredentials` is true.
- **Response `200`**:
  ```json
  {
    "accessToken": "new_eyJhbGciOi..."
  }
  ```

*(Other Auth Endpoints: `POST /auth/forgot-password`, `POST /auth/reset-password`, `GET /auth/verify-email`, `POST /auth/resend-verification`, `POST /auth/logout`)*

## 4. User API (`/users`)
*Requires JWT `Authorization: Bearer <token>`*

### `GET /users/me`
Retrieves the currently authenticated user's profile.
- **Response `200`**: Full user object including `avatarUrl`, `interests`, `travelStyle`, etc.

### `PATCH /users/me`
Updates the user's profile.
- **Body (All fields optional)**:
  ```json
  {
    "display_name": "Ahmed Tarek",
    "bio": "Love traveling to historical places",
    "budget_level": "Mid-range"
  }
  ```
- **Response `200`**: Updated user profile.

### `POST /users/me/avatar`
Uploads a profile picture.
- **Content-Type**: `multipart/form-data`
- **Body**: File uploaded under the field name `avatar`.
- **Response `200`**: `{ "avatarUrl": "..." }`

## 5. Chat & AI Service (`/chat`)
*Requires JWT `Authorization: Bearer <token>`*

### `POST /chat`
Sends a message to the AI assistant. Internally fetches Geo/Risk context and proxies to the Python AI microservice.
- **Body**:
  ```json
  {
    "message": "What is the history of the Pyramids?",
    "lat": 29.9792,
    "lon": 31.1342,
    "conversation_id": "optional-uuid-to-continue-chat",
    "persona": "tour_guide" 
  }
  ```
- **Note**: `lat` and `lon` are optional but heavily recommended so the AI knows where the user is. `persona` defaults to `"auto"`.
- **Response `200`**:
  ```json
  {
    "response": "The Pyramids of Giza were built...",
    "conversation_id": "uuid",
    "persona": "tour_guide",
    "environment": { "weather": "Sunny" }, 
    "geography": { "governorate": "Giza" } 
  }
  ```

## 6. GeoContext API (`/geo`)
*Requires JWT `Authorization: Bearer <token>`*

### `GET /geo/nearby-sites`
Fetches archaeological or tourist sites near the user.
- **Query Params**: `lat` (req), `lon` (req), `radius` (opt), `category` (opt).
- **Example**: `/geo/nearby-sites?lat=30.04&lon=31.23&radius=5000`
- **Response `200`**: Array of site objects.

### `GET /geo/context`
Fetches the full spatial context (governorate, current zone, restricted areas).
- **Query Params**: `lat` (req), `lon` (req), `radius` (opt).
- **Response `200`**: GeoContext JSON object.

---

## 7. Environment API (`/env`)
*Requires JWT `Authorization: Bearer <token>`*

### `GET /env`
Fetches the environmental context (weather, terrain, elevation) based on coordinates.
- **Query Params**: `lat` (req), `lon` (req)
- **Response `200`**: `{ "temperature": "32C", "terrain": "Desert" }`

---

## 8. Risk Intelligence API (`/risk`)
*Requires JWT `Authorization: Bearer <token>`*

### `GET /risk/current`
Gets the current safety/risk status.
- **Query Params**: `city` (opt, e.g., "Cairo").
- **Response `200`**: Safety index object.

### `GET /risk/changes`
Gets recent alerts or changes in safety data.
- **Query Params**: `since` (req, ISO-8601 e.g., "2024-01-01T00:00:00Z"), `city` (opt).
- **Response `200`**: Array of alert objects.

---

## 9. Memory / Trip History (`/memory`)
*Requires JWT `Authorization: Bearer <token>`*

- `GET /memory/history`: Fetch user's saved trips.
- `POST /memory/history`: Save a new trip itinerary.
- `DELETE /memory/history/:id`: Delete a saved trip.
- `POST /memory/preferences`: Save specific travel preferences.
- `POST /memory/feedback`: Submit feedback/rating for a specific place.

## ✅ Frontend Integration Checklist

1. **Test with Swagger**: 
   - Go to `http://localhost:3000/api/docs` and interact with the endpoints to see live request/response payloads before coding.
2. **Setup Axios / API Client**:
   - Create a central Axios instance.
   - Configure `withCredentials: true`.
3. **Setup Interceptors**:
   - **Request**: If `accessToken` exists in state/local storage, append `Authorization: Bearer ${token}`.
   - **Response**: If response is `401 Unauthorized`, catch the error, pause requests, call `POST /auth/refresh`, update the token, and retry the failed requests. If refresh fails, log the user out.
4. **Handle Errors Gracefully**:
   - Catch `400 Bad Request` and map `err.response.data.details` to your UI forms (e.g. underline invalid fields in red).
   - Catch `429 Too Many Requests` on login/register and display "Please wait, too many attempts."
   - Catch `502 Bad Gateway` on `/chat` and display "AI Assistant is currently offline."
5. **Location Permissions**:
   - Prompt the user for location access when opening the map or chat features so you can include `lat` and `lon` in the payloads.
